# 提交复盘索引

本目录从 2026-07-28 起保存项目每次提交的复盘。复盘与对应代码放在同一个
提交中，用于回答“为什么改、实际改了什么、如何验证、还有什么没有做”。

## 文件名格式

```text
YYYY-MM-DD-NNN-<slug>.md
```

- `YYYY-MM-DD`：提交所在地日期；
- `NNN`：当天从 `001` 开始递增的三位序号；
- `<slug>`：小写英文、数字和连字符组成的简短主题；
- 示例：`2026-07-28-001-runtime-consistency-and-queries.md`。

`_template.md` 是模板，不对应提交，也不占用序号。

## 内容要求

每篇复盘至少包含：

1. 提交背景与目标；
2. 纳入和明确排除的范围；
3. 按主题列出的实际改动；
4. 行为、安全、数据或发布契约的变化；
5. 真实执行的测试与验证结果；
6. 遇到的问题、风险和搁置事项；
7. 主要文件清单；
8. 后续动作。

不得写入密码、Token、私钥、真实生产数据或其它秘密。未执行的测试必须写成
“未验证”，不能根据代码推测成“已通过”。

## 使用流程

1. 提交前查看 `git status --short`，区分本次变更和用户已有变更；
2. 复制 `_template.md` 的结构，创建当天的下一个序号；
3. 用最终差异和测试结果填写复盘；
4. 在下方索引增加记录；如果索引与复盘制度尚未进入仓库，可在后续文档提交中
   一次补齐已有记录；
5. 将代码、文档和复盘放入同一个提交。
